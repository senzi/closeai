# P2: 视觉与交互重构 —— 黑白灰科技感动效与非传统「表单」

**优先级：🟡 P2（P0 骨架 + P1 维度系统完成后开始）**
**目标：把「答题」变成一场视觉体验，让用户在黑白灰的科技感中「不知不觉」完成测试。**

---

## 1. 设计系统：黑白灰数据美学

### 1.1 色彩系统

```css
:root {
  /* 核心色 */
  --color-bg: #000000;
  --color-bg-elevated: #0a0a0a;
  --color-bg-card: #111111;
  
  /* 文字色 */
  --color-text-primary: #ffffff;
  --color-text-secondary: #aaaaaa;
  --color-text-tertiary: #666666;
  --color-text-dim: #333333;
  
  /* 强调色 —— 严格限制使用场景 */
  --color-accent: #ffffff;      /* 纯白用于焦点状态 */
  --color-accent-dim: #888888;  /* 中灰用于悬停 */
  
  /* 边框/分割线 */
  --color-border: #222222;
  --color-border-active: #444444;
}
```

**色彩约束**：
- 不使用任何彩色（红/蓝/绿等）。纯粹黑白灰。
- 层次通过明度和透明度区分，而非色相。
- 唯一的「亮点」是白色光效（脉冲、扫描线、粒子）。

### 1.2 字体系统

| 用途 | 字体 | 规格 |
|------|------|------|
| 英文标题 | Space Grotesk | 48-72px, weight 700 |
| 英文正文 | Space Grotesk | 16-18px, weight 400 |
| 中文标题 | Noto Sans SC | 36-48px, weight 700 |
| 中文正文 | Noto Sans SC | 16px, weight 400 |
| 数据/编码 | JetBrains Mono | 14px, weight 400 |
| 标签/辅助 | Space Grotesk | 12-14px, weight 400, uppercase |

### 1.3 间距与网格

- 基础单位：8px
- 页面内边距：桌面端 64px，移动端 24px
- 最大内容宽度：1200px（但大部分内容居中，不需要满宽）

## 2. 核心组件设计

### 2.1 GlitchText —— 故障艺术文字

用于标题、编码、关键信息的「数据损坏」效果。

**效果规格**：
- 文字随机出现横向偏移（`translateX` ±3px）
- 随机出现色偏（RGB 分离，但因为是黑白，所以用灰度分离模拟）
- 随机出现切片（文字被水平切分，上下两部分错位）
- 触发时机： hover、页面切换、关键信息揭示时

```tsx
// components/GlitchText.tsx
interface GlitchTextProps {
  text: string;
  intensity?: 'low' | 'medium' | 'high';  // 故障强度
  trigger?: 'hover' | 'mount' | 'always'; // 触发方式
  className?: string;
}
```

**实现思路**：
- 使用 CSS `@keyframes` + `clip-path` 实现切片效果
- 使用 `text-shadow` 模拟 RGB 分离（在黑白场景下，用 `#fff` 和 `#888` 的叠加模拟）
- 随机性通过 JS 生成随机 `animation-delay` 和 `animation-duration` 实现

### 2.2 DimensionAxis —— 维度滑动轴

用于结果页展示用户在某个维度上的位置。

**视觉效果**：
- 一条水平细线（`1px`, `#333`）
- 一个可拖动的光点（白色圆点，带光晕 `box-shadow`）
- 光点位置 = 得分比例
- 线的两端标注两极名称（如 `AUTONOMY` / `DEPENDENCY`）
- 当光点移动时，细线从光点位置向两侧发出扫描动画

```tsx
// components/DimensionAxis.tsx
interface DimensionAxisProps {
  dimension: {
    code: string;        // e.g. "A/D"
    nameLeft: string;    // e.g. "AUTONOMY"
    nameRight: string;   // e.g. "DEPENDENCY"
    score: number;       // 0 ~ 1，0 = 完全左，1 = 完全右
  };
  animated?: boolean;    // 是否播放入场动画
}
```

### 2.3 ProgressRing —— 答题进度环

替代传统的「第 X 题 / 共 Y 题」进度条。

**视觉效果**：
- 一个细圆环围绕在屏幕角落（右上角或题目区域上方）
- 环的进度 = 已答题数 / 总题数
- 已答部分为白色，未答部分为 `#222`
- 环中心显示当前题号（如 `03`），JetBrains Mono 字体
- 每答一题，环有一个「填充脉冲」动画

```tsx
// components/ProgressRing.tsx
interface ProgressRingProps {
  current: number;    // 当前题号（1-based）
  total: number;
  size?: number;      // 圆环直径，默认 64px
}
```

### 2.4 TypeBadge —— 人格类型徽章

结果页的核心视觉元素。

**视觉效果**：
- 4 个大写字母（如 `ABCE`），Space Grotesk, 72px, weight 700
- 每个字母在一个独立的「数据块」中，块之间有细线分隔
- 字母有轻微的「终端打字机」入场效果（依次出现，伴随光标闪烁）
- 整体外框是一个细线矩形，有轻微的扫描线动画

```tsx
// components/TypeBadge.tsx
interface TypeBadgeProps {
  code: string;       // e.g. "ABCE"
  animated?: boolean;
}
```

## 3. 交互区：非传统「表单」

### 3.1 设计理念

用户不是在做问卷，而是在**接受一场拷问**。所以：

- 没有「上一题/下一题」按钮—— 选择即提交，自动进入下一题
- 没有复选框、没有滑块—— 只有 A/B 两个选择
- 没有题目编号—— 只有进度环暗示进度
- 题目文字不是「问题」，而是「情境」—— 让用户代入

### 3.2 题目展示动画

每道题的入场流程（约 1.2s）：

```
0.0s: 黑屏（或上一题的残留模糊）
0.2s: 题目文字从下方滑入（y: 40px → 0, opacity: 0 → 1）
0.4s: 选项 A 从左侧淡入
0.5s: 选项 B 从右侧淡入
0.6s: 进度环更新
0.8s+: 等待用户选择
```

### 3.3 选项交互

| 状态 | 视觉表现 |
|------|----------|
| 默认 | 半透明白色文字（`#aaa`），无背景 |
| 悬停 | 文字变白（`#fff`），下方出现一条白色细线（`width: 0% → 100%`） |
| 选中 | 文字变白，背景出现反色块（黑字白底），0.3s 后整个选项「碎裂」消失 |
| 转场 | 选中选项放大并向屏幕中心移动，同时屏幕渐黑，准备下一题 |

**选中后的碎裂效果**：
- 使用 CSS `clip-path` 将选项文字切分成 5-7 个水平条
- 每个条向随机方向飞散（`translateX/Y` + `rotate`）
- 同时 opacity 降到 0
- 总时长 0.5s

### 3.4 选项布局

**桌面端**：
- 题目文字居中偏上
- 两个选项水平排列在屏幕下方 1/3 处
- 选项之间有足够的间距（至少 200px）
- 整个布局对称、克制

**移动端**：
- 题目文字居中
- 两个选项垂直排列在下方
- 上下布局，触摸友好

## 4. 结果页视觉

### 4.1 入场动画

答题完成后，屏幕进入「处理中」状态（约 2s）：

```
0.0s: 最后一题碎裂，屏幕渐黑
0.3s: 黑屏中央出现一个白色光点，开始旋转
0.5s: 光点拉成一条横线，横线开始「扫描」整个屏幕（从上到下）
1.0s: 扫描线经过的地方，结果页内容依次显现
1.5s: 扫描完成，TypeBadge 以打字机效果出现
2.0s: 其他内容（描述、雷达图、按钮）依次淡入
```

### 4.3 雷达图/坐标轴

不使用传统的彩色雷达图，而是用**四个独立的 DimensionAxis 组件垂直排列**：

- 每个轴是一条水平线
- 线的中央有一个光点标记用户位置
- 线的两端标注两极
- 入场时，光点从中央向实际位置滑动（带弹性缓动 `ease-out-back`）
- 整个坐标轴区域有微弱的网格线背景（`#111`）

## 5. 动效细节清单

### 5.1 全局动效

| 动效 | 触发 | 实现 | 性能注意 |
|------|------|------|----------|
| 扫描线 | 结果页入场 | CSS animation + mask | 使用 `transform`，避免重排 |
| 噪点纹理 | 全局背景 | SVG filter 或 CSS noise | 静态图片，不要实时生成 |
| 光标闪烁 | 打字机效果 | CSS `animation: blink` | 极低成本 |

### 5.2 微交互

| 交互 | 反馈 |
|------|------|
|  hover 选项 | 文字变白 + 下划线展开 |
|  点击选项 | 选项碎裂 + 屏幕渐黑 |
|  hover 按钮 | 背景反色（黑变白，白变黑）|
|  进度环更新 | 填充脉冲 + 中心数字跳动 |

### 5.3 音效（可选，P2.5）

如果需要音效来增强科技感：

| 场景 | 音效描述 |
|------|----------|
| 开场电影 | 低沉的电子合成器 drone，逐渐升高 |
| 题目出现 | 轻微的「数据加载」声（像老硬盘读取）|
| 选项 hover | 极轻微的「滴」声（类似机械键盘）|
| 选项选中 | 玻璃碎裂声的低频版本 |
| 结果页 reveal | 一个和弦，类似科幻电影里的 AI 觉醒 |

> ⚠️ **注意**：音效需要用户交互后才能播放（浏览器自动播放策略）。建议在用户第一次点击时初始化 AudioContext。

## 7. 待决策问题

1. **结果页的雷达图是否要做成「实时可交互」？** 即用户可以拖动光点，实时看到类型编码变化。这会增加趣味性，但可能让用户困惑。
2. **是否加入「暗模式/亮模式」切换？** 用户要求黑白灰，但纯黑对 OLED 友好，部分用户可能偏好深灰背景。
3. **碎裂效果在低端设备上是否降级？** 可以通过 `prefers-reduced-motion` 和媒体查询检测性能。
4. **JetBrains Mono 是否必要？** 它增加了字体加载量，可以用系统等宽字体 fallback。
